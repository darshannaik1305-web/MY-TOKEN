# My Token (MTK)

A learning and demonstration project that implements an ERC-20 token
using Solidity, OpenZeppelin, Hardhat, TypeScript, and Viem. The
contract has been deployed and its source code verified on the
**Ethereum Sepolia testnet**.

> **Important:** This is a testnet project. MTK is not deployed on
> Ethereum mainnet and should not be treated as a real-value token.
> Never use a wallet containing valuable assets for experiments.

## Features implemented

-   ERC-20 token name and symbol: `My Token` / `MTK`
-   Initial supply of 1 billion MTK assigned to a treasury address
    during deployment
-   Standard ERC-20 functionality, including balances, transfers, and
    allowances
-   Token burning through OpenZeppelin `ERC20Burnable`
-   Signature-based approvals through OpenZeppelin `ERC20Permit`
-   No public mint function
-   No owner/admin role, pause function, blacklist, or transfer tax in
    the current contract

**Supply note:** There is no public function to mint additional tokens
after deployment. However, holders can burn tokens. Therefore,
`totalSupply()` can decrease after deployment. The 1 billion MTK figure
is the initial supply, not an unchangeable minimum or permanent total.

## Requirements

Install the following before setting up the project:

-   Node.js and npm
-   Git
-   A Sepolia-compatible wallet such as MetaMask (needed for deployment
    or wallet interaction)
-   An Alchemy account or another Sepolia RPC provider (needed for
    network access)
-   An Etherscan API key (needed for source verification)

The project was developed with Node.js `v24.19.0`, npm `11.17.0`, and
Hardhat `2.29.1`. Other compatible versions may work, but have not been
confirmed in this project.

## Setup instructions

### 1. Clone the repository

``` bash
git clone <YOUR_GITHUB_REPOSITORY_URL>
cd mytoken
```

Replace `<YOUR_GITHUB_REPOSITORY_URL>` with the repository URL.

### 2. Install dependencies

``` bash
npm install
```

This installs the packages listed in `package.json` and
`package-lock.json`.

### 3. Create your local environment file

The real `.env` file is intentionally excluded from Git because it
contains sensitive values. A template named `.env.example` is included
in the repository.

**Windows PowerShell:**

``` powershell
Copy-Item .env.example .env
```

**macOS / Linux:**

``` bash
cp .env.example .env
```

Open `.env` in your editor and replace the placeholders with your own
values:

``` dotenv
SEPOLIA_RPC_URL=https://eth-sepolia.g.alchemy.com/v2/YOUR_ALCHEMY_API_KEY
PRIVATE_KEY=0xYOUR_DEDICATED_TEST_WALLET_PRIVATE_KEY
TREASURY=0xYOUR_TREASURY_WALLET_ADDRESS
ETHERSCAN_API_KEY=YOUR_ETHERSCAN_API_KEY
```

Do not leave the example placeholders in place if you intend to deploy
or verify.

**Security rules**

-   Never commit `.env`.
-   Never share your private key or wallet recovery phrase with
    teammates, in screenshots, in issues, or in chat.
-   Never put real secret values in `.env.example`.
-   Do not use a wallet containing real funds for testnet experiments.
-   If a private key is exposed, consider that wallet compromised.
    Create a new wallet and stop using the exposed one.
-   The `TREASURY` value is a public address, but confirm it carefully
    before deployment because the constructor sends the initial supply
    there.

Each teammate should create their own local `.env`. Do not send one
person's private key to the whole team.

## Compile the smart contract

``` bash
npx hardhat compile
```

Hardhat compiles the Solidity files using the compiler and settings in
`hardhat.config.ts`. The project currently uses Solidity compiler
`0.8.28` and the Cancun EVM target.

## Run automated tests

``` bash
npx hardhat test
```

The current test suite includes checks for:

-   Token name and symbol
-   Initial supply
-   Initial treasury allocation
-   Rejection of the zero address as treasury
-   Token transfer
-   Token burning and total-supply reduction
-   Permit signature-based approval

At the time this README was written, the test run completed with **16
passing tests in total**: 8 MTK tests and 8 tests for the Hardhat
starter `Lock` example.

Tests run on Hardhat's local test environment. Passing tests do not mean
the contract has undergone an independent security audit.

## Check the configured Sepolia wallet

After setting the `.env` values, run:

``` bash
npx hardhat run --network sepolia scripts/check-wallet.ts
```

This script prints the connected chain ID, configured wallet address,
and wallet balance.

The expected Sepolia chain ID is:

``` text
11155111
```

The deployer wallet needs Sepolia test ETH to pay gas for deployment and
other state-changing transactions. Obtain test ETH from a reputable
Sepolia faucet. Test ETH has no intended real-world value.

## Deploy to Sepolia

> **Warning:** Deployment creates a new contract and spends Sepolia test
> ETH. Do not run this command just to inspect the existing contract.
> The existing deployed address is listed above.

After confirming the RPC URL, private key, treasury address, and testnet
balance, run:

``` bash
npx hardhat run --network sepolia scripts/deploy.ts
```

The deployment script:

1.  Connects to the configured wallet.
2.  Reads the `TREASURY` address from `.env`.
3.  Deploys `MyToken` and passes the treasury address to the
    constructor.
4.  Prints the new contract address.

Save the address printed by the script. Every deployment creates a
separate contract instance.

## Read the deployed token information

The current `scripts/check-token.ts` script is configured with the
existing deployed contract address and treasury address. Run:

``` bash
npx hardhat run --network sepolia scripts/check-token.ts
```

It reads the token name, symbol, decimals, total supply, and treasury
balance from Sepolia.

If you deploy a new contract or change the treasury, update the
addresses in this script before using it.

## Verify the contract on Etherscan

The existing contract has already been verified. For a new deployment,
use the new contract address and the exact constructor argument used
during deployment:

``` bash
npx hardhat verify --network sepolia <NEW_CONTRACT_ADDRESS> <TREASURY_ADDRESS>
```

For the current deployment, the verification command was:

``` bash
npx hardhat verify --network sepolia 0x46d877f12066f38bb0a5fb9556ed6e9d1f83f671 0x6338beaf201ec3750f2350572f3579c500c7379f
```

Verification requires the Etherscan API key in `.env` and matching
compiler settings, source code, and constructor arguments. Verification
publishes the source code for inspection; it does not change or upgrade
the deployed contract and is not a security audit.

## Important contract behavior

The constructor sets the token name and symbol, checks that the treasury
address is not the zero address, and mints the initial supply to the
treasury.

The contract inherits:

-   `ERC20`: standard token functionality
-   `ERC20Burnable`: allows token holders to burn tokens
-   `ERC20Permit`: supports signature-based approvals

There is no public mint function. There is also no owner/admin role,
pause mechanism, blacklist, or transfer tax in the current version.
